What merges into experimental/main

  • The cycle completed, with its report written. Partial, reset and aborted cycles never merge.
  • It has commits.
  • The post-cycle gate is green on a clean checkout.
  • The merge review says MERGE. It gets three attempts, and no clear answer counts as REJECT.
  • The merge is always a fast-forward. Nothing is ever force-pushed.

Rejected work isn't thrown away. The next cycle starts from experimental/main, reads why the previous one was rejected, and cherry-picks what's sound from attempts/<run>/cycle-NN.

How the backlog moves

An item's life

  1. openSeeded from audits and your notes (B-000 to B-008), or added by a cycle, always with evidence.
  2. checkedReview: scouts test it against the code as a hypothesis. It's confirmed, already fixed, or wrong.
  3. in-progressPlan: chosen for this cycle and given acceptance checks.
  4. doneRecord: closed with its commits and evidence once it's verified.
  5. droppedClosed with a reason. Items are never deleted.
  6. newAnything a cycle finds but doesn't fix becomes a new item for later cycles.

These files merge with the cycle, so each cycle reads the backlog and handoff as the last merged cycle left them. A rejected cycle's notes stay on its attempts branch for the next cycle to read.

The manager's six options

CONTINUEThe cycle is progressing: give it 10–120 more minutes. NUDGESend the agent one steering message, which it reads as coming from the operator. RESTART_SESSIONA fresh pi session on the same workspace, with a briefing. NEW_CYCLEClose this cycle as partial. It's tagged but not merged. RESET_TO_LAST_GOODTag the head as abandoned and restart the working branch from experimental/main. ABORT_RUNStop everything for a person to look at.
