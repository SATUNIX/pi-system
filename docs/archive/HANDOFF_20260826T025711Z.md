## Non-negotiable invariants (do not violate any of these — §7 of the proposal)
1. `conductor` never enforces scope/ROE and never becomes a gate itself.
   `pentest-governance-domain` remains the sole deterministic authority. If
   Phase 1 code touches scope/ROE files at all, it may only read them, never
   decide access on their behalf.
2. `conductor` never returns `{ systemPrompt }` and never injects a system
   prompt directly. It may only write `.pi/agents/*.md` files and a
   context-sieve **contribution** file (same pattern as
   `extensions/orchestrator/index.ts`'s `contribFile()` — see that function).
   `context-sieve` stays the sole injection authority. The kit's own
   self-containment lint in `npm run verify` checks this — if it starts failing
   after your change, you have violated this invariant.
3. Any assembly this phase does (there should be very little — Phase 1 has no
   synthesis) must be deterministic template/data assembly, never a live model
   free-writing behavior.
4. Least privilege: whatever this extension registers should ask for no more
   than it needs. Do not widen any existing tool's permissions to make this
   easier.
5. Fail closed: see the verifier-board gating requirement above. No phase may
   advance on missing, stale, or unreadable verdict state.
6. Bounded recursion / budget caps are a Phase 4 concern — not applicable yet,
   but do not write anything in Phase 1 that would make Phase 4's caps harder
   to add later (e.g. do not hardcode unbounded dispatch loops).
7. Everything audited: engagement-record writes and phase transitions should be
   observable via `trace-ledger` (check `extensions/trace-ledger/index.ts` for
   its recording API/pattern before inventing a new one).
