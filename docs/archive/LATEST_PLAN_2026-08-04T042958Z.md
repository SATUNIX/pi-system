# `misc-agents-pi-kit` Production-Readiness Plan (0.4.1 → 1.0.0)

## Context

`misc-agents-pi-kit` is a catalogue of extensions, skills, vendor packages, profiles, and docs for the `@earendil-works/pi-coding-agent` framework — the "pi agent" the user runs alongside Claude Code, used partly for OffSec/pentest work (parent dir `OffSec/AI Area`; skills include `authz-idor-testing`, `burp-web-triage`, `scope-roe-governance`). It's at v0.4.1. A prior Claude session (Opus 4.8) already audited it and left two docs: `docs/roadmap.md` (authoritative release-criteria roadmap) and `docs/improvement-roadmap.md` (a prioritized, ROI×Effort-tagged shortlist, capability-ladder framed: trust → efficiency → recovery → verification → memory). Neither has been acted on — the roadmap commit is the current tip of the work.

The user asked for a detailed plan to take the kit to a clean, production-ready 1.0 — extensions, profiles, docs, and "robust systems and mechanisms" — built on the existing roadmap rather than replacing it, broken into epics/sprints with definitions of done, then to start hardening the system on a branch.

**Repo hygiene already done:** committed a pending `themes/gitops-dark.json` change, confirmed local `main` matches `origin/main` (fetched, 0/0 diff), and created branch `hardening/production-readiness-plan` off the current tip (`c1b5df5`, 9 commits ahead of `main`).

**Verification pass on the existing roadmap docs** (spot-checked directly against code, not taken on faith) found both are stale or incomplete in several concrete, high-impact ways — most importantly: **`tool-firewall` — the extension every profile relies on as a safety boundary — ships default-allow-all with no policy file anywhere in the repo**, and neither existing doc mentions this. That finding reorders the plan: security hardening moves ahead of general capability work, immediately after the trust/stub-audit pass both docs already call for first.

## Part A — Corrections to the existing roadmap docs

Verified directly against code (file:line), not from the prior session's doc alone:

1. **`tool-firewall` defaults to allow-all, silently.** `extensions/tool-firewall/index.ts:20-23`: `DEFAULT_POLICY = { defaults: { unknown: "allow" }, tools: {} }`. `policyPath()` (line 37-40) returns `null` unless `PI_KIT_FIREWALL_POLICY` is set — nothing in the repo sets it, no policy JSON exists anywhere. It's `enabledByDefault: true` in **all 5 shipped profiles**, including `quick`. This contradicts `skills/governance-extension-maintainer/SKILL.md`'s own documented invariant ("fail closed... unknown tools must deny, never default-allow"). Bigger than anything in improvement-roadmap.md §1. Confirmed live.
2. **`remote-review` is a full stub, missing from the existing §1 stub-audit list.** `extensions/remote-review/index.ts:5,15`: `"remote-review: loaded (stub)"` / `/escalate` → `"remote-review: TODO"`. Ships in `profiles/autonomous.json` and `profiles/self-improving.json` — confirmed via grep. `autonomous` is not an experimental tier, so an unattended run relying on `/escalate` silently does nothing.
3. **Extension↔profile manifest metadata is drifted**, undetected by any check. Spot-checked `secret-guard`: `extensions/secret-guard/extension.json` claims `"profiles": ["quick", "balanced", "self-improving"]`; it's actually included in all 5 (`autonomous`, `long-horizon` too — confirmed via grep). Since `docs/EXTENSIONS.md` generates from this metadata, the published catalogue is wrong. Prior agent's estimate of ~16/37 drifted entries not independently re-verified in full here, but the pattern is confirmed real.
4. **No git tags exist** (`git tag -l` → empty) despite 10 commits of semver-labeled history (0.2.1 → 0.4.1) and a documented tag-based install path (`docs/INSTALL.md`, `pi install git:...@vX.Y.Z`). No `CHANGELOG.md`. Confirmed both absent. improvement-roadmap.md §7 tags the release-convention item ROI *low* — given zero tags exist and the install path depends on them, this should be ROI **high**.
5. Every `extension.json` `status` field is uncalibrated (blanket `"experimental"` except `secret-guard`), including extensions that are clearly real (`pentest-governance-domain`, `verifier-board`, `task-graph`, `goal-core`, `orchestrator`) — not flagged in either doc.
6. `secret-guard`'s detection is filename/string regex only (`extensions/secret-guard/index.ts:4-25`) — trivially bypassed via copy or encoding. Not flagged anywhere.
7. §2's "skills catalogue is drifted" claim is **not currently true** — all 36 `SKILL.md` dirs match `docs/skills-catalogue.md` 1:1 today. Real forward risk, not an active bug; re-scope, don't drop.
8. §6's "pi-version drift" framing is imprecise: there's no devDependency pin on `@earendil-works/pi-coding-agent` at all, only a `peerDependencies` floor of `>=0.76.0` against an installed `0.79.6` — an *untested range*, not a pin mismatch.

## Part B — Epic → Sprint → DoD roadmap

Sequenced trust → **security** → organization → verification → recovery → memory → docs → release → capstone (security elevated ahead of general efficiency/capability work, given finding #1 and the kit's OffSec usage). Each epic maps to a version bump.

### Epic 1 — Trust Baseline & Cross-Platform Hygiene (`0.4.2`)
Every extension enabled in a non-experimental profile does what it claims; cross-platform friction on every commit/export/install is gone.

- **1.1 Cross-platform hygiene.** Add `.gitattributes` (`* text=auto eol=lf`, binary excludes for themes/native binaries). EPERM-tolerant retry in `kit/export-package.mjs:220`'s `rmSync`. Ensure `kit/install.mjs`'s surface path runs `npm install` in the generated `dist/pi-kit-lite` before `pi install` registers it, or fails loudly with a fix instruction. Detect the `lean-ctx` binary at `session_start`, warn/disable cleanly instead of `spawn ENOENT`.
  **DoD:** no CRLF/LF warning on commit; `node kit/export-package.mjs --surface lite` run twice back-to-back (with a stale read-only artifact present) succeeds both times, no manual `chmod`; clean-machine `npm run install:lite` either works or fails with a clear message; missing `lean-ctx` binary produces one warning, not a crash.
- **1.2 Stub audit & quarantine.** Remove `mcp-router` and `remote-review` from `surfaces/lite.json` / `profiles/autonomous.json` / `long-horizon.json` / `self-improving.json` (or gate behind `PI_KIT_ENABLE_EXPERIMENTAL=1` with a loud banner listing every stub loaded). Fix the stale `"Stub:"` comment on `extensions/memory-mem0/index.ts:9` (it's real). Re-assign every `extension.json` `status` to `stable`/`beta`/`experimental`/`stub` based on actual maturity.
  **DoD:** every extension in a non-experimental profile reports status other than `experimental`/`stub`; `autonomous`/`long-horizon` profiles and the lite surface no longer silently include non-functional stubs.
- **1.3 `verify.mjs` guards.** New check: fail if a non-experimental-profile extension emits a literal `"(stub)"`/`": TODO"` string, or has `status` `stub`/`experimental` while `enabledByDefault: true` anywhere non-experimental. New check: bidirectional cross-validation of `extension.json.profiles` vs. `profiles/*.json.include`, fixing all drifted entries found.
  **DoD:** `npm run verify` fails when a stub string or profile-metadata drift is reintroduced (prove by reverting one fix); passes clean on HEAD otherwise. No CI file changes needed — CI already runs `npm run verify`.

### Epic 2 — Safety Boundary Hardening (`0.4.3`)
The kit's own trust/safety extensions hold the line they document, provably, not just by being present. Directly addresses finding #1, the single biggest gap found.

- **2.1 Default-deny `tool-firewall` + shipped starter policy.** Change `DEFAULT_POLICY.defaults.unknown` from `"allow"` to `"ask"` (interactive) / `"deny"` (headless). Ship a real starter policy (`kit/policies/default.json`) covering common high-risk tool patterns; `policyPath()` falls back to it instead of `null`.
  **DoD:** a fresh session with zero env vars loads the shipped policy (rules > 0, not silent allow-all); new `tests/tool-firewall-smoke.mjs` asserts a known-destructive tool call resolves to `ask`/`deny`, wired into a new `npm run test:security` CI step.
- **2.2 `secret-guard` hardening.** Add content-aware heuristics beyond filename matching; cover common bash bypasses (`cp`/`mv`/`base64`); cross-link `pentest-governance-domain`'s `PROTECTED_PATTERNS`/`DESTRUCTIVE_COMMANDS` (`extensions/pentest-governance-domain/index.ts:55-79`) so the two lists can't silently diverge.
  **DoD:** `npm run test:security` asserts a `.env` write is blocked, a secret-copy bash command is blocked, a destructive `rm -rf` is blocked/asked — all in CI.
- **2.3 Security documentation baseline.** Add `SECURITY.md` (what the firewall/secret-guard/governance boundary guarantees and explicitly does not). Audit `quick`/`balanced` profile description copy against actual post-2.1/2.2 defaults.
  **DoD:** `SECURITY.md` exists, linked from `README.md` and `mkdocs.yml`; profile descriptions match real defaults.

### Epic 3 — Organization, Catalogue & Docs-Nav Automation (`0.5.0`)
Catalogues generated, not hand-maintained; nav reflects real structure.

- **3.1 `kit/skills-catalogue.mjs`**, modeled on `kit/registry.mjs`. Add `category:` frontmatter to all 36 `SKILL.md` files; regenerate `docs/skills-catalogue.md`; wire into `npm run catalog`.

  **DoD:** target SKILL.md bodies shrink to runbook shape; frontmatter description unchanged.
- **3.3 mkdocs nav regroup + generated capability matrix.** Group the ungrouped top-level nav entries into Guides / Design & Roadmap / Reference. Add a generated `docs/capability-matrix.md` (profile → extensions → task class) built from `profiles/*.json` + `extension.json`.
  **DoD:** `python -m mkdocs build` succeeds, no broken links; capability matrix is script-generated, not hand-edited.
