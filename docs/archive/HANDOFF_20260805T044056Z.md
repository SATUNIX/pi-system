## Known issues / blockers
All of the following are documented with file:line evidence and independent repro steps in `reviews/FINAL-review.md` — this list is a pointer, not a restatement. Do not start fixing without reading the linked section first.

- **Blocking (F-01…F-06):** profile selection is metadata-only (installer ignores `selected`); shipped firewall/governance policy blocks first-party tools (`subagent`, `task_create`, `record_verdict`, `memory_store`) by default, especially headless; native Windows destructive commands and elementary secret-copy/encoding bypass the safety boundary; lockfile can't reproduce a clean install; the "full profile regression" capstone gate is a metadata check, not the real install+verify+eval regression.
- **High (H-01…H-09, AG-01, AG-02, AG-04, AG-05, AG-06):** dream-mode path authorization is substring-based and bypassable; `branch-lab` tools use the wrong execute signature; `provider-router` doesn't actually route inference and has no real task-type input in production; `orchestrator` never executes the workflow it scores; `git-checkpoint` clears restore points before use; `skill_archive` allows path traversal; recovery orchestration is scaffolding; canonical install docs point at a nonexistent `v0.1.0` tag; the release cutter is unsafe; the docs-freeze claim is false against HEAD; verification can pass without running a real check or on a race; compaction silently drops goal/verdict/handoff continuity instructions.
- **Systemic pattern to keep in mind while fixing:** multiple independent findings (H-03, AG-01, AG-02, AG-05) share one root shape — an extension computes the correct decision/instruction and returns or writes it, but nothing downstream actually consumes or enforces it. When fixing any one of these, check whether the fix needs to happen at the *consumption* point (Pi core's hook-return handling, or the missing caller) rather than at the *producer* (the extension that already "looks" correct). Treat this as a design smell to watch for in code you haven't touched yet, too.
