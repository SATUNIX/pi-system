# Predetermined evaluation

Offline fault injection runs the baseline cyber scoring block in memory twice with a complete six-case request matrix and an empty existing finding, and twice with no request log. Null controls: incomplete matrix must fail; missing file must not qualify as a completed report. Inspect timing boundaries and completed-message usage recording directly.

Acceptance: missing/corrupt evidence yields durable failed/error cases without losing subsequent cases; report review remains explicitly pending regardless of matrix success; empty report fails behavior deliverable checks. Preserve failed-run usage, represent unknown/incomplete metrics explicitly, and separate process duration from evaluator scoring.

Regressions and holdouts: deterministic event streams for normal completion, interrupted generation, absent usage, cache usage, malformed events; missing and corrupt boards; per-case exception followed by successful case. No model calls in these probes.

Live smoke, when coordinator grants capacity: existing hello and coding prompts from kit/eval/live/run.mjs, optionally synthetic cyber prompt, focused surface, one repetition, existing default 24 tool calls and 100 shared relay requests, 180-second case timeout. Scoring changes must not alter agent prompts or runtime boundaries. Alternate surface/lifecycle control is reserved to coordinator. Report quality requires independent review; no automatic claim-grounding model will be invented.
