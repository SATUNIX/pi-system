## What passed and why this remains a failure

`npm run verify`, `npm run test:security`, `npm run eval` (13/13) and eight targeted smokes passed: verification lifecycle, progress guard, recovery grounding, subagent progress, task graph invariants, conductor recursion, compaction continuity and install profile filtering. Logs are `baseline-*.log` in this directory. The review runner confirmed 16 baseline scenarios and the footer runner reproduced two defects. A confirmed counterexample is not a passing release requirement.

Existing fakePi keeps one handler per event; composed tests can overwrite earlier registrations. Most tests stop at queued strings or contribution files rather than executing resulting turns and checking terminal scheduling. Footer tests accept an invented API/event shape. Task tests validate task_complete but miss task_update(done). Short compaction tests preserve their marker inside the retained prefix. Known shell-pattern tests cannot establish arbitrary native-effect allowlisting. Historical findings that profile filtering, policy tool coverage and lockfile parity were broken have received meaningful fixes; those blanket findings are not repeated here.

The new runner preserves all lifecycle handlers, consumes custom/user follow-ups differently, uses deterministic counters and a fixed seed, fakes verification, prohibits native/network calls and checks actual Pi runner ordinary dispatch/short-circuit methods. It is intentionally incomplete: no full AgentSession/provider scheduler, streaming race model, restart persistence, process trees, timers, OS isolation, generated interleaving exploration or mutation testing. It does not fulfill the eventual full simulator acceptance gate. The failed first S14 setup used the manual cap path without its following turn_end; corrected setup now exercises the actual automatic cap handler. No failing production behavior was patched to make these observations green.
